# 费用预算表页面交付记录

日期：2026-09-09。范围：当前仓库的 VTable 页面及其共用业务层，沿用现有演示数据和业务变更回调。

## 本次修复

| 问题 | 交付行为 |
| --- | --- |
| 连续滚动可能积压过期分页请求 | 最多 3 个分页并发；显式读取优先；最新视口保留，过期预取取消 |
| 一页成功可能清除另一页的错误并触发重试循环 | 按页保留错误，显示失败行范围；用户主动重试，不会静默重复请求 |
| 迟到、错页或残缺响应可能污染缓存 | 校验投影 ID、页码和行数；取消后的结果不可写入缓存 |
| 主控制器混合缓存、附件和业务命令 | 分页调度、批注附件拆为独立模块，工作台支持注入业务网关 |
| 批量修改后的历史计算影响滚动 | 仅打开历史面板时计算所选单元格历史；批量回调让出主线程 |
| 编辑时打开侧栏，校验与焦点不一致 | 先完成同一笔保存，再打开侧栏；错误输入保留并聚焦 |
| 超大粘贴先构建完整矩阵 | 解析阶段限制单元格数量，拒绝超限内容且不发写请求 |
| 长期演示会话累积达到 100 个，阻止新页面加载 | 页面退出/路由卸载释放会话，服务端关闭幂等；保留过期清理兜底 |
| 底部折叠后适配列宽可能改变滚动位置 | 列宽适配共用视口恢复逻辑，保留必要的底部展示留白 |

## 验收方式

- 生产构建运行真实预算 API，Chrome 中操作真实 Canvas、输入框、键盘及剪贴板。
- 常规模式与 101,100 行模式均验证编辑、公式、撤销重做、复制粘贴、拖拽、搜索定位、独立层级、行列调整、批注附件和完整统计。
- 故障注入覆盖慢分页、部分失败、过期响应、取消请求和手动重试。
- 逻辑测试覆盖有界并发、请求优先级、LRU、失败恢复、尾页完整性、超限粘贴，以及 120 次会话建立与释放。
- 截图检查桌面与 390px 窄屏；检查未捕获的页面错误及分页响应数量。

首轮完整回归为 57 / 58。唯一失败项在 Canvas 绘制前读取到未选中底色作为像素基准；6 次诊断确认绘制后与滚动后的选区颜色一致。测试现等待实际绘制并额外断言选中底色，保留原有颜色容差和单层图元要求，最终全量通过。首轮报告保留在 `playwright-report/vtable-delivery-first/`，最终报告位于 `playwright-report/vtable-budget/`。

TanStack 回归的网络采样同步改为监听 `requestfinished`，避免读取主动取消的预取响应；原有分页行数、缓存上限、编辑和搜索断言均保留。最终类型检查及浏览器兼容回归通过。

### 十万行性能记录

本机 Chrome，1600 × 1000，生产构建，无 CPU/网络节流：

| 操作 | 本次实测 |
| --- | --- |
| 进入十万行模式 | 612 ms |
| 定位到尾页 | 248 ms |
| 尾页编辑保存 | 271 ms |
| 1,617,600 格完整选区统计 | 800 ms |
| 全内容列宽适配 | 1,398 ms |
| 上述定位、编辑、统计流程的最长主线程任务 | 246 ms（初始化） |

定位/保存/统计流程仅有 4 个 `page` 响应，分别为 200、200、100、100 行；没有下载全部 101,100 行。列宽适配仅返回 200 + 80 条显示样本，额外下载业务行数为 0，期间记录 71 个动画帧。缓存最多 10 页 / 2,000 行，分页最多 3 个并发；慢网测试验证旧请求取消，最新视口可正常显示。

桌面、390px 窄屏截图：`test-results/vtable-product-desktop.png`、`test-results/vtable-product-mobile.png`。数值是本次测试记录，初次绘制仍有短时主线程工作，不能据此承诺任意设备与网络下零卡顿。

## 使用与接入

```bash
pnpm dev
# http://localhost:8000/vtable

pnpm test:vtable
pnpm test:tanstack
pnpm typecheck:vtable

# 停止开发服务后进行生产构建/回归
pnpm build
pnpm serve:budget
pnpm test:vtable:e2e
pnpm test:tanstack:e2e
```

开发编译器与生产构建共用 `dist/`，两者不可同时写入该目录。浏览器报告在 `playwright-report/`，截图及 trace 在 `test-results/`，这些生成目录均被 Git 忽略。

本次按确认的仓库范围交付。金额、公式、批注和附件仍是演示会话数据，刷新重置。正式业务保存应实现 `BudgetGateway`，并通过 `BudgetWorkbench.gateway` 注入；金额持久化与版本冲突校验应位于后端，批注附件需接正式存储。原 `onBusinessCellChange` 保持成功后的通知语义。

项目仍包含其他表格研究引擎，完整构建有原有的大体积依赖提示；VTable 路由有独立测试确认不会加载 SpreadJS 引擎脚本。性能记录仅代表本机、指定窗口和网络环境，不是跨设备耗时保证。

开发预览已恢复至 `http://localhost:8000/vtable`，最终页面检查无未捕获错误。干净桌面截图为 `test-results/vtable-delivery-final.png`。
