# 业务表格组件：选型结论与 Demo 验收标准

更新时间：2026-08-21

## 1. 已确认的产品定义

- 产品定位是业务数据表，不追求完整复刻 Excel。
- “下钻 / 上钻”是在数据粒度之间切换；汇总单元格可进入下一层明细，并通过面包屑返回。它与同表中的行展开 / 折叠是两项独立功能。
- “撤销 / 重做”只覆盖单元格值修改，包括输入、清空、区域粘贴和批量填充。一次区域粘贴视为一个原子操作。排序、筛选、列宽、显隐和折叠不进入撤销栈。
- “数据追踪”是任意派生值的完整计算来源和聚合链路，不限于求和。追踪链路应包括计算规则、中间指标、筛选条件、转换规则和最终原始记录。
- “单元格历史”只记录值变化。
- 批注为简单批注，不需要回复、@成员或解决状态。
- 批量复制支持跨行跨列的矩形区域。
- 自定义统计允许用户选中区域并配置聚合公式。
- 行分组和列分组都支持多级嵌套。

## 2. 评分口径

需求权重沿用原调研表：高 = 5，中 = 3，低 = 1。能力状态不直接等同于“库是否宣传支持”，而按实际交付成本分为：

- `原生`：组件直接提供可用能力。
- `轻扩展`：监听事件或添加一个自定义渲染器即可完成。
- `业务层`：必须建立独立的数据模型、服务或交互面板。
- `不适合`：能力方向与产品定位冲突，或实现代价不合理。

“持续维护”和“生产许可”是门槛项，不通过时不以功能总分抵消。

## 4. 当前建议

### 首选：VTable

选择理由：

- MIT 许可，可以交付无水印、可部署的 Demo，不被尚未确定的采购决策阻塞。
- 采用 Canvas 渲染，官方重点覆盖百万级数据展示。
- ListTable 原生支持树形数据、子节点懒加载和多级行折叠。
- 列定义可以形成多级树，并支持分层展开 / 折叠。
- 已有编辑器、搜索、右键菜单、区域复制粘贴、列宽拖动和内容自适应能力。
- 当前缺少的撤销、批注、历史、血缘、附件恰好都属于边界清晰的业务能力，可以通过统一的 `cellKey` 数据模型实现。

主要风险：

- 撤销栈需要自行实现，并保证区域粘贴是单个事务。
- Canvas 表格中的复杂浮层、无障碍支持及中文输入法需要重点验收。
- 业务编辑器和公式型统计不能与组件内部状态强耦合。

### 商业备选：AG Grid Enterprise

选择理由：

- 与业务数据表定位最一致。
- 区域复制、单元格撤销、多级行分组、多级列组、选区聚合、服务端行模型等能力成熟。
- 数据源、编辑事件和自定义组件边界清晰。

限制：满足本项目核心需求会用到 Enterprise 能力，正式部署前必须解决许可证问题。因此它适合作为商业方案对照，不作为当前无许可前提下的默认交付内核。

### 不进入第一轮 Demo 的方案

- **Handsontable**：编辑和电子表格交互成熟，也支持嵌套行与可折叠列，但商业使用需要许可证；对当前业务表格和大数据目标的综合优势不及 AG Grid Enterprise。
- **Univer**：更适合完整电子表格。多级行列 Outline 属于 Pro，产品形态偏 Office，超出当前业务表格需求。
- **SpreadJS**：内置能力最完整，甚至提供文件上传单元格，但属于商业电子表格方案，功能和许可都偏重。
- **AntV S2**：强项是多维交叉分析和透视展示，不适合作为高频业务数据编辑内核。
- **Jspreadsheet**：偏电子表格，生产和高级扩展需要商业许可，对当前场景没有明显优势。
- **Luckysheet**：官方仓库已归档并明确不再维护，不进入新项目。

## 5. Demo 功能验收标准

### A. 基础表格与编辑

1. 提供文本、数字、日期、单选、复选框、状态和附件等示例列。
2. 编辑成功后立即更新数据；非法数字、日期或枚举值不能静默写入。
3. 支持拖动改变列宽；双击列边界按当前内容自动调整列宽。
4. 用户可以通过列管理器显示或隐藏列，固定业务主键列不可隐藏。
5. 快速搜索可匹配当前数据集中的可见业务字段，并支持上一个 / 下一个匹配项。

### B. 选择、复制与撤销

1. 鼠标可选中任意矩形区域，复制内容以制表符和换行符组织，可直接粘贴到 Excel 或文本编辑器。
2. 从外部复制的矩形数据可粘贴到起始单元格；只读列被跳过并给出提示。
3. 一次区域粘贴产生一个撤销事务；撤销后所有受影响单元格恢复，重做后整体再次生效。
4. 输入、清空、填充和粘贴都进入同一个有界撤销栈。
5. 排序、筛选、下钻、折叠、列宽和显隐不会污染撤销栈。

### C. 行列分组与钻取

1. 行至少展示三级嵌套，例如“大区 → 省份 → 城市 / 门店”，各层可独立展开和收起。
2. 列至少展示三级嵌套，例如“经营指标 → 收入 → 订单收入 / 服务收入”，父组收起后保留汇总列。
3. 行子节点支持异步加载，加载中、空结果和失败状态明确可见。
4. 汇总单元格可下钻到下一数据粒度；顶部面包屑显示当前路径。
5. 上钻返回时恢复上一层的筛选、排序、折叠和滚动位置。

### D. 批注、附件与历史

1. 右键单元格可新增、修改、删除简单批注；有批注的单元格显示稳定标记。
2. 右键单元格可查看值历史，历史至少包含旧值、新值、时间和操作来源。
3. 附件单元格支持选择文件、上传状态、文件名、大小、预览 / 下载和删除。
4. 批注、附件和历史以稳定 `rowId + columnId` 关联，不以当前屏幕行列序号关联；排序、过滤和钻取后仍指向正确数据。

### E. 自定义统计与计算血缘

1. 选中区域后可选择 `SUM`、`AVG`、`COUNT`、`MIN`、`MAX` 或一个受控的自定义聚合表达式。
2. 统计面板展示参与计算的有效单元格数、被忽略的空值 / 非法值和最终结果。
3. 派生值右键可打开“数据追踪”，以树形结构展示当前结果、运算规则、中间节点和原始来源。
4. 血缘节点显示输入值、运算符、筛选条件、去重 / 空值 / 单位转换等处理规则。
5. 中间节点可继续展开，来源记录可跳转到对应明细或触发下钻。
6. 原始值没有上游计算时，显示来源记录和字段，而不是伪造计算过程。

### F. 性能与稳定性

1. 使用 1 万行 × 50 列作为常规数据集，10 万行 × 50 列作为压力数据集。
2. 记录首次可交互时间、滚动流畅度、快速搜索耗时、展开大分组耗时和区域粘贴耗时。
3. 大数据模式不得一次为所有单元格创建 DOM 节点。
4. 快速连续编辑、撤销、折叠、搜索和下钻不能出现数据错位。
5. 至少验证当前版本 Chrome、Edge 和 Safari。

## 6. 业务层接口边界

正式 Demo 不把业务能力写死在 VTable 内部，至少定义以下边界：

- `TableDataSource`：分页 / 分块加载、排序、筛选、分组子节点和下钻数据。
- `CellMutationService`：校验并提交单个或批量单元格修改。
- `UndoManager`：只记录值修改事务。
- `CellCommentService`：按稳定单元格 ID 管理简单批注。
- `CellHistoryService`：查询值变化记录。
- `AttachmentService`：上传、查询、下载和删除附件。
- `LineageService`：返回派生值的计算图，并提供来源记录定位信息。
- `AggregationService`：对选区执行内置或受控自定义聚合。

此设计允许后续把模拟数据源替换为真实接口，也允许在采购确定后把 VTable 替换为 AG Grid，而不重写历史、批注、附件和血缘模型。
