# 透视表（多维度行树 × 列树 × 指标）需求文档 v2

> 版本：v2.0（对应 `docs/PivotPrototype.md` 任务文档 v8）  
> 读者：产品、业务、前后端开发、测试。本文只描述**需求**（做什么）；实现细节见任务文档。

---

## 1. 背景与目标

业务需要一张**类透视表的可编辑表格**，业务原型为"**组织 × 科目 × 期间 → 指标值**"：

- 行方向两条层级树：**组织**（华润微电子集团 → 华润微电子本部 / 华晶公司）、**科目**（费用汇总 → 费用-办公费 / 费用-电费 / 费用-水费）；
- 列方向：**期间**（Q1 / Q2 → 月份）+ **指标**（预算数 / 实际数 / 完成率…）；
- 行 = 组织 × 科目的**全节点交叉**（**父节点也作为数据行常驻**，带汇总值）；值 = 行 × 期间列 × 指标 的交叉聚合，可编辑并支持**后端回写分摊**；
- 支持**增量更新**、大数据量扩展、**单元格历史**。

## 2. 术语定义

| 术语 | 含义 |
|------|------|
| 行维度 | 行方向的层级树（组织、科目），每个维度占一列，层级缩进展示 |
| 行（数据行） | 组织树节点 × 科目树节点的组合（父节点也参与），如 (集团, 办公费) |
| 属性列 | 跟随后端行维度列的可编辑列，保存该维度节点的附加信息（日期/文本/下拉） |
| 列维度 | 列方向的可折叠层级树（期间：Q1/Q2 → 月份） |
| 指标 | 值列的最底层（预算数/实际数/完成率…），挂在期间叶子下，**不可折叠** |
| 对称/非对称 | 列树各分支子项结构是否一致（如 Q1/Q2 都含 1、2、3 月 = 对称；Q1 含 1、2 月而 Q2 含 2、3 月 = 非对称） |
| 维度层 / 指标层 | 列结构中可折叠的树部分（维度层）与固定的叶子列尾（指标层）；**只有维度层允许折叠** |
| 折叠 | 隐藏某节点的后代行/列；行节点保留自身行，列组折叠后出"各指标的聚合列"（方案 a） |
| 保存制 / 脏标记 / 回写分摊 / 增量更新 / 单元格历史 | 同 v1 定义 |

## 3. 功能需求

### 3.1 表格结构（FR-1）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-1.1 | 行 = 组织 × 科目全交叉 | 行集 = 组织树全部节点 × 科目树全部节点（含 (集团, 费用汇总) 合计行）；demo 全展开 12 行 |
| FR-1.2 | 父节点常驻 | 父组织/父科目都是数据行，显示其汇总值，不随展开消失 |
| FR-1.3 | 行维度单列树 + 合并 | 每个行维度一列；节点行块内组首行显示标签并**跨行合并**，缩进表示层级 |
| FR-1.4 | 属性列 | 每个行维度一个属性列（组织属性、科目属性…），位置可配置；属性属于维度节点、与维度列**同步合并**；可编辑，格式：日期/文本/下拉 |
| FR-1.5 | 列结构 = 维度层 + 指标尾 | 列 = 期间树（维度层，可折叠）+ 指标（叶子列尾，永不折叠）；demo 3 层表头：Q → 月 → 指标 |
| FR-1.6 | 对称 / 非对称期间 | 列树分支形状自由：对称（Q1/Q2 均含 1、2、3 月）或非对称（Q1 → 1、2 月，Q2 → 2、3 月）；**不同分支的同名节点（Q1 的 2月 与 Q2 的 2月）互相独立** |
| FR-1.7 | 指标列挂载 | 指标（预算数/实际数/完成率…）挂在每个期间叶子（月份）下，列名可配、数量可变 |
| FR-1.8 | 配置驱动 | 行/列维度的数量、层级、名称、顺序、属性列位置均可配置，不写死 demo 结构 |

### 3.2 折叠 / 展开（FR-2）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-2.1 | 行节点折叠 | 折叠组织节点 → 隐藏其后代组织节点的行块，保留自身行块；折叠科目节点 → 各组织块内隐藏其后代科目行，保留科目自身行 |
| FR-2.2 | 列维度折叠（仅维度层） | **只有维度层节点可折叠**：Q1 折叠 → 隐藏月份层，显示**各指标的聚合列**（预算数合计/实际数合计/完成率合计，= 该 Q 各月之和）；**月份层与指标层不可折叠** |
| FR-2.3 | 全部展开 / 折叠 / 重置 | 工具栏一键操作 |
| FR-2.4 | 纯前端交互 | 折叠/展开不请求后端（查本地聚合矩阵） |

### 3.3 编辑（FR-3）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-3.1 | 可编辑范围 | **可编辑**：全部指标值列、属性列；**只读**：行维度列、列维度表头 |
| FR-3.2 | 值列编辑 | 叶子×叶子（组织叶×科目叶×期间叶×指标）= 直接改明细；**含父节点的格** = 记录意图值，保存时后端裁决（分摊或拒绝） |
| FR-3.3 | 对称/非对称不影响编辑 | 所有指标列均可编辑，无只读派生列 |
| FR-3.4 | 属性编辑 | 三格式（日期原生选择器 / 文本 / 下拉选项），节点级配置 |
| FR-3.5 | 保存制 | 编辑仅本地生效 + 脏标记（角标 + 计数），点「保存」批量提交；有未保存修改时离开需确认 |
| FR-3.6 | 输入拦截 | 非数字/负数（值列）当场拒绝；等值变更不产生脏；改回原值自动消脏 |
| FR-3.7 | 维度组合信息 | 编辑时携带单元格对应的行组合（组织节点路径 + 科目节点路径）与列组合（期间路径 + 指标），随载荷提交 |
| FR-3.8 | 保存反馈 | 成功/失败/冲突均有提示与日志（`[pivot-edit]`/`[pivot-save]`） |

### 3.4 回写分摊（FR-4，后端）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-4.1 | 策略 | 按比例（默认）/ 平均；原值 0 时退化为平均 |
| FR-4.2 | 数值精确 | 取整后 Σ 明细 === 编辑值（最大余数法） |
| FR-4.3 | 覆盖范围 | 该格覆盖的明细 = 组织叶×科目叶×期间叶×指标 中属于 (行节点子树 × 列节点子树) 的记录 |
| FR-4.4 | 空集拒绝 | 无对应明细时拒绝并提示 |
| FR-4.5 | 前端零计算 | 聚合/分摊全部后端；前端查表渲染 |

### 3.5 数据加载与更新（FR-5）

| 编号 | 需求 | 说明 |
|------|------|------|
| FR-5.1 | 初始加载 | 明细 + 各级聚合值矩阵 |
| FR-5.2 | 增量更新 | 保存后仅返回变化闭包（值真正变化的聚合格 + 明细），前端打补丁；仅 首次/409 冲突/结构变化 才全量 |
| FR-5.3 | 并发冲突 | 版本号乐观锁，冲突提示并重拉 |
| FR-5.4 | 大数据扩展 | 按需分块加载（行侧演示） |
| FR-5.5 | 结构切换 | demo 支持期间"对称/非对称"切换（后端结构与矩阵同步重建） |

### 3.6 单元格历史（FR-6，同 v1）

右键可编辑单元格查看历史：时间 / 操作人 / 旧值→新值 / 类型（手动/分摊）/ 影响明细数 / 版本；后端审计，只读展示。

### 3.7 计算规则（FR-7，后端）

聚合规则**按指标**配置（求和 / 加权 / 自定义，demo 提供切换）；保存时后端只增量重算受影响闭包。

### 3.8 其他（FR-8）

说明卡片（结构/折叠状态/版本摘要）；控制台数据打印（明细/矩阵/表格行、编辑载荷、保存载荷）。

## 4. 非功能需求

| 编号 | 需求 |
|------|------|
| NFR-1 | 性能：保存响应与改动范围相关；不整表重拉；列/行重建只与可见结构相关 |
| NFR-2 | 一致性：展示值以后端矩阵为准；Σ 精确；折叠聚合列与明细一致 |
| NFR-3 | 并发：版本号 + 冲突提示重拉 |
| NFR-4 | 可维护性：mock 后端接口可替换为真实 HTTP；前端不含计算规则 |
| NFR-5 | 兼容性：现代浏览器；Handsontable 18 + React 18 |

## 5. 边界与例外

1. 折叠仅限维度层；月份（子级为指标）与指标层不可折叠；Q 折叠形态 = 方案 a（各指标聚合列）。
2. 保存前父行/折叠列显示旧值 + 脏标记（前端零计算，既定设计）。
3. 聚合格编辑由后端裁决（规则不允许/冲突/空集可拒绝）。
4. 假设：一个 (组织叶, 科目叶, 期间叶, 指标) 组合一条明细；多记录时更新范围由后端决定。
5. 不做：撤销/回滚、权限、实时协同（仅冲突提示）、导出、维度拖拽增删。

## 6. 验收要点

1. 全展开 = 组织 3 节点 × 科目 4 节点 = 12 行；对称期间 = 18 个指标值列；表头 3 层正确。
2. 行树/列树折叠符合 FR-2：Q1 折叠出 3 个指标聚合列且值 = 3 月之和；月份/指标表头点击无效；行折叠保留自身行。
3. 非对称切换（Q1:1、2月 / Q2:2、3月）：列数与值正确，Q1 的 2月 与 Q2 的 2月 互不影响。
4. 编辑 → 保存 → 各级聚合一致；分摊 Σ==编辑值；增量仅含变化格。
5. 属性列三格式可编辑、与维度列同步合并。
6. 历史 / 冲突 / 脏标记 / 未保存提醒符合 FR。
